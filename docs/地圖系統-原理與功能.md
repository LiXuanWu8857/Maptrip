# Maptrip 地圖系統 — 原理、邏輯與功能

> 本文件說明 Maptrip 的地圖從「引擎選擇 → 初始化 → GPS 進來 → 清理/貼路 → 畫線 → 朝車頭旋轉 → 底圖切換」整條鏈的原理與相關功能。
> 對應程式：`js/gl-compat.js`、`js/orient.js`、`js/snap.js`、`js/geo-gate.js`、`js/geo-clean.js`、`js/app.js`（initMap / 繪線 / 圖磚）、`index.html`（引擎選擇 loader）、`sw.js`（圖磚快取）。

---

## 0. 一句話總覽

Maptrip 有**兩套地圖引擎**（標準＝Leaflet、向量＝MapLibre GL），但 `app.js` 只寫一套 Leaflet API；向量引擎靠 `gl-compat.js` 這層「相容層」把 Leaflet 呼叫翻成 MapLibre 呼叫，所以**上層程式碼完全不分引擎**。GPS 點進來後會經過「品質閘門 → 飄移清理 → 道路貼合 → 三重防假路線 → 繪製」的流水線，地圖本身可以**朝車頭旋轉**、街道文字保持正立。

## 1. 雙地圖引擎

| | 標準（預設後備） | 向量（Beta） |
|---|---|---|
| 函式庫 | Leaflet 1.9.4 + `leaflet-rotate` | MapLibre GL 4.7.1 |
| 底圖 | Google 圖磚（點陣 raster） | OpenFreeMap Liberty 向量圖磚 |
| 相容層 | 原生 Leaflet | `js/gl-compat.js`（把 Leaflet API 翻成 GL） |
| 旋轉時街名 | 會跟著轉（點陣圖整塊旋轉） | **保持正立**（向量文字即時重繪）＝向量引擎的最大賣點 |
| 記憶體 | 較省 | 較吃（WebGL），Safari 分頁易崩 |

### 1.1 為什麼要相容層？
`app.js` 用到的是 Leaflet 的 API（`L.map`、`L.polyline`、`L.marker`、`map.setView`、`map.setBearing`…）。`gl-compat.js` 實作了**這些 API 的子集**，底層轉成 MapLibre GL 呼叫。好處：**切換引擎時 `app.js` 一行都不用改**，向量壞了直接不載入這層、退回原生 Leaflet 即可。

座標/縮放慣例（相容層對外一律維持 Leaflet 慣例）：
- 座標：`[lat, lng]`
- 縮放：Leaflet zoom（＝ GL zoom + 1）
- 方向：`setBearing` 用 leaflet-rotate 方向（＝ −GL bearing）

## 2. 引擎選擇與失敗保險（血淚史）

引擎選擇在 `index.html` 的 loader 決定，用 localStorage 旗標 `maptrip_gl`：

- **App 內（原生殼）預設向量**：`maptrip_gl==='0'` 才關。
- **瀏覽器（Safari 後備）預設標準**：`maptrip_gl==='1'` 才開（Safari 分頁記憶體上限低，向量容易崩）。

### 2.1 GL 失敗旗標 `mt_glfail`
GL 一旦出問題，寫入時間戳 `mt_glfail`，**接下來 3 小時強制走標準地圖**；`mt_glfail_reason` 記錄原因，開機時用 toast 告訴使用者：

| reason | 意義 |
|---|---|
| `crashloop` | 30 分鐘內被系統砍 4 次（記憶體崩潰迴圈） |
| `reloadloop` | 180 秒內自動重載 >4 次 |
| `loadfail` | 資源載入失敗 |
| `jsfail` | GL 建構/執行期丟例外 |

### 2.2 `gl-compat.js` 的多重保險（全都會「默默退回標準」）
1. **maplibregl 不存在** → 直接 `return`（index 驗到 `MAPTRIP_GL` 沒設就走標準）。
2. **WebGL 探測**：先建一個 1×1 canvas 拿 WebGL context；WKWebView 的 GPU 行程剛被砍時建 context 會失敗 → 探測不過就不啟用（否則 `maplibregl.Map` 會 throw、開機半途死掉、按鈕全無反應）。探測完立刻 `loseContext()` 釋放。
3. **關鍵 CSS 內建**：`maplibre-gl.css` 若從 CDN 載入失敗，少了 `touch-action:none` 這條，iOS 會把手勢當頁面捲動 → 地圖完全不能拖/縮。相容層直接注入最必要的規則，CDN 掛了照樣可操作。
4. **Map 建構 throw** → 記 `jsfail` + `safeReload`。
5. **webglcontextlost** 5 秒未復原 → `safeReload`。
6. 省記憶體：隱藏 3D 建築（`fill-extrusion`）、`pixelRatio≤2`、`maxTileCacheSize:24`。

## 3. 地圖初始化 `initMap()`（`app.js`）

### 3.1 leaflet-rotate 手勢鎖定修補（重要）
`leaflet-rotate` 有個作者自留的 @TODO bug：**雙指「同時」縮放＋旋轉**會讓圖層變換與內部座標脫鉤（實測每次手勢偏移約 7px 且會累積）——這就是「縮放時路徑亂跑、貼不回地圖」的元兇。

修補成 **Google 地圖式手勢鎖定**：一次手勢只能二擇一（先達門檻者鎖定）：
- 縮放比例 `|log2(scale)| > 0.12` → 鎖 `zoom`（停用旋轉）
- 旋轉角 `|dB| > 12°` → 鎖 `rotate`（停用縮放）

旋轉角用 `atan2` 走最短路徑（`atan(x/y)` 在 y<0 時會多出 ±180° 假旋轉，純捏合會被誤鎖成旋轉）。另外 `_onTouchStart` 包裝裡**預先給定 `_center/_zoom`**，否則旋轉鎖定分支拿到 `undefined` 會炸掉、地圖從此壞死（zoom=NaN、無法歸位）。

### 3.2 地圖選項
```js
L.map('map', { zoomControl:false, attributionControl:false, zoomSnap:0,
               preferCanvas:false,          // 必須用 SVG：Canvas 與 leaflet-rotate 不相容，旋轉+縮放線會錯位
               rotate:true, rotateControl:false, touchRotate:true, shiftKeyRotate:false, bearing:0 })
```

### 3.3 今日行程專用圖層 pane
建立 `todayLines`（z=410）與 `todayMarks`（z=620）兩個 pane，讓「歷史檢視」時能**整組**隱藏今日行程（`pane.style.display='none'`），不必逐一追蹤每條線/每個標記（漏追蹤就會出現「今日的點外漏」）。

## 4. 地圖朝向 / 羅盤 / 朝車頭（`js/orient.js`）

目標：行駛時地圖**朝車頭方向**旋轉，指北針針頭永遠指真北。

- **雙來源方向**：
  - 靜止/低速 → 手機**羅盤**（DeviceOrientation）
  - 行駛 → **GPS 行進方向**（`bearingBetween` 由連續兩個「有前進」的點算方位角）
- **平滑旋轉動畫**：`requestAnimationFrame` 緩動 `_animBearing → _targetBearing`；角度用累積器保證 CSS transition 走最短路徑（不會為了轉 10° 繞 350°）。
- **發燙防治（血淚三元兇之一）**：羅盤原本 60Hz 抖動會不停驅動旋轉動畫 → 加**節流 + 死區 2.5°/3°**，靜止時不重畫。
- **方向光束**：「我的位置」標記帶一個扇形光束，指出目前朝向。
- **對外介面**：`cancelBearingAnim()`（地圖手勢一開始就停掉自動旋轉，讓使用者手動操作優先）、`syncBearingFromMap()`、`resetBearingNow()`（單趟/日預覽固定指北）。
- **回放/單趟檢視讓路**：回放中所有自動運鏡與朝車頭都退讓。

## 5. GPS 資料流水線（點進來到畫上去）

```
GPS 點
  │
  ▼ ① 品質閘門  geo-gate.js  MaptripGeoGate.accept()
  │     精度 > 40m 不記錄；相對前點瞬移 > 50 m/s(≈180km/h) 不記錄
  ▼ ② 逐點收錄（app.js onGpsUpdate，GPS 熱路徑刻意留在 app.js）
  │     即時畫 activePolyline（記錄中的藍線）
  ▼ ③（行程結束/重試）飄移清理  geo-clean.js  cleanTrace()
  ▼ ④ 道路貼合  snap.js  snapToRoads()（OSRM /match → /route 後備）
  ▼ ⑤ 三重防假路線
  ▼ ⑥ 繪製  drawTripLine() / tripPath()
```

### 5.1 品質閘門 `geo-gate.js`
源頭擋髒資料：水平精度 > 40m、或相對前一個已接受點瞬移 > 50 m/s，就**不記錄**。回傳 `{accept, reason}`（reason ∈ ok/accuracy/teleport）。

### 5.2 飄移群清理 `geo-clean.js`
都市峽谷反射、停等紅燈會產生「來回鋸齒 / 原地小圈」飄移群：
- **`_dropSpikes`（視窗式，往前看 4 點）**：收孤立飄點。判準＝繞行 > 2.5× 且多繞 60m，且（端點 <35m＝甩回原地 或 垂距 apex > 端距 2×＝尖刺），並要求第一個中間點自己就偏離 >15m（避免連坐正常直行點）。
- **`collapseStalls`（v276，停等紅燈原地飄移「圈」）**：從上個保留點 a 出發，若一段路徑「在小範圍內（離 a `<CAP=100m`）繞了不少路（via≥100m）、點數≥5 後又繞回 a 附近（<35m）」＝原地飄移 → 整叢收成一點。**CAP=100m 是關鍵護欄**：真的繞街廓（半徑通常 >100m）先超過 CAP 而不被收，只收侷限小圈。
- `cleanTrace` 先跑 `collapseStalls` 再跑 `dropSpikes`；迭代 4 趟（安全閥：≥25 點才防過度清理；collapseStalls 的收斂不納入 40% 安全閥）。
- 真實繞街廓/轉彎（有前進、apex≈端距）不誤刪。

### 5.3 道路貼合 `snap.js`（OSRM）
把 GPS 軌跡「吸附」到真實道路上。用公開 OSRM 伺服器：
- **`/match`（Map Matching）自適應降階取樣 95→60→40→25**：TooBig 就逐級縮小點數。（2026-07 起連 25 點也常被拒＝伺服器收緊。）
- 全被拒 → **後備 `/route`**：把取樣點當途經點近似。
- 貼路成功後 coords 壓縮成頭尾（原始軌跡不可復原）；失敗重試上限 `_snapN` 15 次。
- 飄移群不進貼路（先 `MaptripGeoClean.cleanTrace`）。

### 5.4 三重防假路線
OSRM 有時把飄點硬吸成「繞遠的假路線」，用三道防線擋：
1. **`_dropSpikes`**（清理層）：孤立飄點先剔除。
2. **`_snapSane`**（長度檢查）：`/match` 結果 >原始 1.4×+500m、`/route` 更嚴 1.2×+200m 就棄用、保留原始軌跡。
3. **`tripPath()`**（顯示層防線，見 §6）：就算假路線被雲端同步蓋回本機，畫面也不顯示。

另有 `healBogusRoads`（每次開機掃描修復）與 `slimTripForStorage`（同步入口剝除假路線，否則合併評分讓假路線永遠贏、造成同步無限來回）。

## 6. 路線繪製（`app.js`）

### 6.1 `tripPath(t)` — 取一趟的可畫座標（顯示層防假路線）
優先用 `roadCoords`（貼路後），否則退回 `coords`（原始 GPS）。**假路線防線**：若 `roadCoords` 長度 > 記錄距離 `totalDist × 1.4 + 500m`＝飄點造成的繞遠假路線 → 這趟永不顯示貼路、退回原始座標。結果快取在 `t._roadBad`，不必每次重算。極舊雲端資料可能沒座標 → 一律回傳陣列（可能空），呼叫端遇空就略過（一趟壞資料絕不能讓整個載入/預覽/回放迴圈死掉）。

### 6.2 `drawTripLine(trip, idx)`
今日路線畫成藍線（`#1A73E8`，weight 5），掛在 `todayLines` pane；點線可進入該趟單趟預覽。

### 6.3 `drawGapLine(from, to)` — 兩趟之間的連接
用二次貝茲曲線（向外彎 0.25）畫紅色虛線，表示「上一趟結束 → 下一趟開始」的空車移動。

### 6.4 折線脫鉤修正 `redrawAllLines()`（v247，標準地圖）
leaflet-rotate 手勢式「縮小＋旋轉」後，SVG 折線幾何有時沒重算、整條飄離底圖（點/標記正常，只有線脫鉤；投影本身是對的）。在 `zoomend/moveend/`去抖 rotate 後，**強制以目前投影重畫所有折線**（allMapLayers / soloLayers / dayPreviewLayers / replayTempLayers / activePolyline）。GL 模式沒有這問題（`l.redraw` 不存在自動略過）。
另有 `resyncLiveLine()`：縮放/手勢期間累積、沒畫進去的點，結束後從記錄座標一次補上。

### 6.5 今日圖層三態 `_todayMode`
| 狀態 | 意義 | 線 | 點 |
|---|---|---|---|
| `normal` | 一般 | 顯示 | 顯示 |
| `hidden` | 歷史檢視時整組隱藏 | 隱藏 | 隱藏 |
| `solo` | 今日單趟預覽 | 0.12 淡化 | **整組隱藏** |

任何狀態下的重畫（`drawTripLine`/`drawGapLine`）都會套用當前狀態（`_applyTodayMode`），修正兩個外漏源：(1) 貼路成功/同步的重畫發生在歷史檢視期間、新圖層原本以全濃度冒出；(2) 今日單趟的「點」淡化在 GL 會被引擎重繪蓋回全濃度 → 改為整組隱藏。

**GL 陷阱**：MapLibre 每次 render 會重寫 marker 元素的 `style.opacity` → 要隱藏 marker 必須用 `display:none`（相容層的 `Marker.setOpacity(0)` shim 已改為 display）。

## 7. 底圖圖磚與記憶體

### 7.1 標準地圖圖磚
- Google 圖磚：道路 `lyrs=m`、衛星 `lyrs=y`，`maxZoom:20`。
- **`keepBuffer:0`**：畫面外的圖磚立刻釋放（Leaflet 預設留 2 圈；解碼點陣圖是背景記憶體大戶）。
- `updateWhenIdle:true`：拖動中不狂載圖磚。

### 7.2 背景時卸圖磚
`visibilitychange` 進背景時卸掉 Google 圖磚（減少被 iOS 因記憶體壓力砍掉的機率）；回前景再載。

### 7.3 Service Worker 圖磚策略（`sw.js`）
- 導覽（HTML）：**網路優先 + no-store**、4 秒逾時/離線退快取（隧道白屏救星）。
- 自家 `?v=` 資源與鎖定版本函式庫（leaflet / maplibre / openfreemap styles|sprites|fonts）：**快取優先**。
- **Google 圖磚與向量圖磚不攔截**（交給瀏覽器/引擎自己管理，避免快取爆量）。
- 快取名帶版本、`activate` 汰舊。

## 8. 單趟 / 日預覽底圖切換

進入單趟預覽或某日的日預覽時：
- 底圖切成**白色無標示**（CartoDB nolabels；深色模式用深色版 `NOLABEL_DARK/LIGHT`），退出還原。
- 今日路線畫藍色、歷史路線畫黑色，路徑上有編號。
- 固定指北（`resetBearingNow()`）；左右滑切上/下一趟；有截圖鈕。

## 9. 台灣道路標誌（`gl-compat.js`，向量引擎）

OpenFreeMap Liberty 用 OpenMapTiles schema（道路編號在 `transportation_name` 圖層，欄位 `class`＝等級、`ref`＝編號）。Liberty 內建的是國際盾牌，相容層改成**台灣式**：

| 類型 | 判準（依台灣公路編號範圍） | 盾牌 |
|---|---|---|
| 國道 | `class=motorway`（先判等級） | 綠色梅花 |
| 快速公路 | 台 61–88 | 紅盾 |
| 省道 | 台 1–39 | 藍盾 |
| 縣道 | 100–299（三位數） | 黃牌 |

鄉道/區道等地名字首（北37、南113、竹35…）會跳過（`台/臺/國/省/縣/道/號` 不算地名）。校準工具：`MaptripTwShields.sample`。

## 10. 穩定性機制彙整（與地圖相關）

背景：WKWebView 網頁行程會被 iOS 因記憶體壓力砍掉（司機同時跑導航 App 時最兇）。地圖相關的保護：

- **開機看門狗**：25 秒未 `__mtBooted` → `safeReload`。
- **防迴圈重載**：180 秒窗 >4 次 → `reloadloop` → 停止並轉標準 3 小時。
- **崩潰偵測 v3（心跳式）**：`app.js` 每 5 秒寫 `mt_alive`；載入時「導覽型態＝navigate 且 mt_alive <45 秒」＝被系統砍掉 → 30 分鐘窗累積 4 次 → `crashloop` → 標準 3 小時。
- **GL 全路徑保險**：見 §2.2。
- `native/MainViewController.swift`：`didBecomeActive` 探測 JS 環境（`typeof INDEX_VERSION`），死了就 `webView.reload()`——背景被砍回來全白的原生解。

診斷：**歷史行程底部版本號連點 3 下**開黑盒子（`mt_bootlog` 環狀 80 筆：page navigate/reload、bg/fg、crash-restart、boot ok、watchdog、safeReload）；連點 5 下＝診斷模式。
