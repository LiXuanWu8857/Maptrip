# Maptrip 行程回放（Replay）— 功能與運作邏輯

> 對象：`js/app.js` v1.1.257 的回放區塊（約 `let replayDot…` 到 `updateReplayPanel()`，~290 行）。
> 目的：說明回放**做什麼**、**怎麼運作**、**跟哪些東西耦合**——後者是之後把它拆成 `replay.js` 模組的藍圖。

---

## 1. 功能總覽

把「某一天的所有行程」像影片一樣**在地圖上重播**：一個亮點（replay dot）沿著當天每一趟的路線依序移動，鏡頭跟著跑，面板顯示「第幾趟／共幾趟、時間、里程」，可**暫停**、可調**1–20 倍速**。

- **兩種入口**：
  - **今日回放** `openReplay()`：回放 `todayTrips`（記憶體中今天的趟）。
  - **歷史回放** `replayDay(dayKey)`：回放歷史某一天；會先把那天的路線用藍線臨時畫出來當背景，再重播。
- **可回放門檻** `_replayable(t)`：一趟至少要有一個座標點（`roadCoords || coords`）。舊雲端資料有些趟沒座標，不濾掉會讓 `startReplay` 拋例外、整個回放卡死，所以入口一律先 `filter(_replayable)`。

---

## 2. 狀態變數（這就是為什麼難拆——一整組活狀態）

| 變數 | 意義 |
|---|---|
| `replaySet` | 目前回放的趟陣列（今日或歷史某日） |
| `replayTripIdx` | 現在播到第幾趟（0 起算） |
| `replayCoords` | 當前趟的座標（優先 `roadCoords`，較平滑） |
| `replayProgress` | **浮點**索引：在 `replayCoords` 上的位置（可為 3.4 = 第 3、4 點之間 40%） |
| `replayDot` | 地圖上的亮點 marker |
| `replayRAF` | `requestAnimationFrame` 的 handle（動畫迴圈；也被外部當「回放中」旗標） |
| `replayPaused` | 是否暫停 |
| `replaySpeed` | 倍速 1–20 |
| `replayLastTs` | 上一個影格時間戳（算 dt 用） |
| `replayPauseTimer` | 一趟結束後停留 2 秒的計時器 |
| `replayTempLayers` | 歷史回放時臨時畫的藍線（關閉時清除）；**被 `redrawAllLines` 讀取** |
| `replayTripCenter / replayFitZoom / replayCloseZoom` | 運鏡用的範圍中心與縮放層級 |
| `_replayHidToday` | 歷史回放時是否把「今日圖層」藏起來了（關閉要還原） |

---

## 3. 核心運作：以「時間」為基準的平滑動畫

回放不是「每點跳一格」，而是**依真實經過時間內插座標**，所以任何倍速都平滑不晃。

### 3.1 動畫迴圈 `replayFrame(ts)`
每一個瀏覽器影格（約 60fps）呼叫一次：
1. **暫停**中就原地等（保留 RAF 迴圈）。
2. 算 `dt = ts − 上次時間戳`，**上限 100ms**（App 從背景切回前景時，避免一次暴衝一大段）。
3. **前進**：`replayProgress += dt × (replaySpeed / 200)` → 1 倍速約 **5 點/秒**。
4. 若 `replayProgress ≥ 最後一點` → 畫最後一格 → 進入**趟結束轉場**。
5. 否則畫這一格 → 排下一個影格。

### 3.2 畫一格 `renderReplayFrame()`
用 `replayProgress` 的整數部分 `i` 與小數部分 `frac`，在 `coords[i]` 與 `coords[i+1]` 之間**線性內插**出 dot 的經緯度：
```
lat = a.lat + (b.lat − a.lat) × frac
```
然後 `replayDot.setLatLng(...)`＋`map.panTo(dot, {animate:false})`——**鏡頭每格跟著 dot 平移**（不加動畫，靠高頻更新自然順）。

### 3.3 一趟啟動 `startReplay()` / `setupReplayTrip(idx)`
- `setupReplayTrip`：設定 `replayCoords`、歸零 `replayProgress`、用 `L.latLngBounds` 算出整段範圍中心與縮放（`map.getBoundsZoom`，預留上方狀態列/下方面板空間）。
- `startReplay`：先 `stopReplay()` 清乾淨 → 建立 `replayDot` marker → `frameReplayTrip()` 把整段路線框進畫面（**每趟只設一次相機**，避免逐格縮放閃爍）→ `updateReplayPanel()` → `startReplayRAF()` 起跑。

---

## 4. 趟與趟之間的轉場

`endOfTripTransition()`：一趟播完後——
1. 停 RAF，`replayTripIdx++`。
2. 若已是最後一趟 → `finishReplay()`（面板顯示「回放完畢」、toast）。
3. 否則 `setupReplayTrip(下一趟)`、更新面板，**停留 2 秒**後呼叫 `glideGap()`。

`glideGap(from, to, onDone)`：沿著 `bezierGapPoints` 產生的**紅色貝茲連接線**，把 dot 快速滑到下一趟起點（約 0.6 秒、**與倍速無關**），滑完 `onDone()` → 歸零 progress、重新框景、重啟 RAF。

---

## 5. 速度控制 `initSpeedSlider()` / `onSpeedSlider(v)`

- 速度條用 **iOS 原生 scroll**（不用 touchmove，最可靠）：拖動 `#speed-scroll-hitarea` 的 `scroll` 事件 → 換算 ratio → `1 + ratio×19`（1–20x）。
- iOS 捲動慣例反向，所以用 `1 − ratio` 讓「右邊＝快」。
- `window._syncSpeedScroll`：面板顯示後才量得到正確寬度，故對外開放讓入口呼叫一次同步捲動位置。

---

## 6. 鏡頭運鏡與「讓路」機制

- **回放中所有自動運鏡都要讓路**：`isReplaying()`（看 `#replay-panel` 有沒有 `.show`）為 true 時，App 每秒的 GPS 跟隨／羅盤旋轉／5 秒歸位**全部停手**——否則鏡頭會被拉回目前位置，回放就壞了。
- 框景用 `frameReplayTrip()` → `fitMapToRoute(...)`（每趟一次）；跟隨靠 `renderReplayFrame` 的 `map.panTo`。

---

## 7. 歷史回放的圖層處理

`replayDay()` 進入歷史回放時：
1. `showTodayLayers(false)`＋把 `activePolyline` 透明度設 0 → **把「今日」的線與標記全藏起來**（避免和歷史線混淆），記 `_replayHidToday = true`。
2. 逐趟用 `L.polyline` 把該日路線畫成藍線、趟間用 `drawGapLine` 連接，全部推進 `replayTempLayers`。

`closeReplay()` 關閉時：`stopReplay()`＋`clearReplayTempLayers()`（移除藍線）＋若 `_replayHidToday` 就 `showTodayLayers(true)` 還原＋隱藏面板＋（若有定位且非 solo/日預覽）5 秒後 `scheduleFollowResume()` 自動飛回目前位置恢復跟隨。

---

## 8. 相依與耦合（拆模組的重點）

這是回放**比 util/geo/snap/screenshot 難**的原因——它不是純函式，而是**有活狀態＋操作地圖鏡頭＋被外部反向引用**。

### 8.1 需要注入的
- **Leaflet `map` 物件**（app.js 私有 `let map`）：`map.panTo / getBoundsZoom / removeLayer`、以及 `L.marker/divIcon/polyline/latLngBounds/point`（`L` 是全域，OK）。**這是第一個要注入 map 的模組。**

### 8.2 對外反向引用（要開放存取器、改這 2 處）
- `replayTempLayers` 被 **`redrawAllLines()`**（折線脫鉤修正，app.js ~1029 行）讀取 → 要開 `MaptripReplay.tempLayers()`。
- `replayRAF` 被某處當「**動畫進行中**」旗標判斷（app.js ~2305 行）→ 要開 `MaptripReplay.isAnimating()`。

### 8.3 呼叫的全域函式（執行期由 window 取用，可直接用）
`loadTrips`、`toast`、`closeSheet`、`closeHistory`、`exitDayPreview`、`showTodayLayers`、`tripPath`、`drawGapLine`、`bezierGapPoints`、`fitMapToRoute`、`scheduleFollowResume`、`fmtTime`、`fmtDist`。

### 8.4 讀取的其他 app.js 狀態（要注入或開放）
`todayTrips`、`activePolyline`、`currentPos`、`soloSet`、`dayPreviewKey`、`_wantFollowResume`。

### 8.5 DOM 元素
`#replay-panel`、`#replay-play-btn`、`#replay-trip-label`、`#replay-trip-info`、`#speed-value`、`#speed-fill`、`#speed-thumb`、`#speed-scroll-hitarea`。

### 8.6 公開函式（app.js 留薄包裝、HTML onclick 零改動）
`openReplay`、`replayDay`、`closeReplay`、`toggleReplayPause`、`onSpeedSlider`、`initSpeedSlider`、`isReplaying`（`isReplaying` 被 app.js 多處呼叫來「讓路」，要保留全域）。

## 9. 拆模組建議做法（下一批）

1. 建 `js/replay.js`＝`MaptripReplay`，把 §2 的整組狀態搬進模組。
2. `MaptripReplay.init({ map, getTodayTrips, getActivePolyline, getCurrentPos, ... })` 注入 `map` 與需要讀的 app.js 狀態存取器。
3. 開放 `tempLayers()`／`isAnimating()`，把 app.js 的 2 處反向引用（`redrawAllLines`、~2305 行旗標）改成呼叫它們。
4. app.js 留公開函式的同名薄包裝（`openReplay`/`replayDay`/`closeReplay`/`toggleReplayPause`/`onSpeedSlider`/`initSpeedSlider`/`isReplaying`）→ 呼叫端零改動。
5. `index.html` 於 app.js 前載入 `replay.js`。
6. 測試（回歸較難，聚焦這些）：模組存在＋薄包裝委派；用 **stub map** 跑一遍生命週期（`openReplay`→影格推進→`endOfTripTransition`→`closeReplay`）不丟錯；`isReplaying()` 開關正確；`tempLayers()`/`isAnimating()` 反向引用可用；開機無 pageerror。

> **心法**：其他模組能「逐字搬＋薄包裝」是因為它們無狀態、不碰 map。回放是**第一個需要依賴注入（map＋狀態存取器）**的模組——所以要單獨一批、謹慎做，別跟別的混在一起。
