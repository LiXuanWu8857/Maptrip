# 記帳者模式 — 功能與運作邏輯

> 版本基準：v1.1.267（2026-07-30）
> 相關檔案：`js/bookkeeper.js`（前端面板）、`js/sync.js`（Firestore 雲端邏輯）、
> `js/desktop-mode.js`（電腦版記帳者模式）、`docs/記帳者-firestore規則參考.md`（安全規則，**安全根**）

---

## 1. 這是什麼

讓「司機以外的人」（家人、記帳人員）幫司機**填每趟的抽成／叫車費**，
而**看不到、也改不到行程本身**。行程對記帳者唯讀，只有抽成欄位可寫。

一個帳號**同時是兩種角色**（看你怎麼用）：

| 角色 | 視角 | 能做什麼 |
|------|------|----------|
| **司機** | 「授權我的記帳者」 | 產生邀請碼、看／撤銷已授權的記帳者 |
| **記帳者** | 「我協助記帳的司機」 | 輸入邀請碼綁定司機、看該司機行程（唯讀）、編輯每趟抽成 |

同一個記帳者可協助多位司機；同一位司機可授權多位記帳者。

## 2. 資料模型（Firestore）

```
invites/{code}                        邀請碼（司機產生 → 記帳者兌換 → 司機自動授權）
  driverUid, driverName, createdAt, exp
  claimedBy, claimedName               ← 記帳者兌換時回填
  revoked: true                        ← 司機撤銷該記帳者時標記（見 §3.4）

users/{driverUid}/
  meta/profile        { name }         司機名稱
  meta/access         { bookkeepers: { <bkUid>: <bkName>, ... } }   ← 授權清單（安全根）
  days/{YYYY-MM-DD}   { trips: [...] } 行程（記帳者唯讀）
  commissions/{tripId} { commission, dispatch, updatedAt, by }      抽成（記帳者可寫）

users/{bkUid}/
  linkedDrivers/{driverUid} { name, since }   記帳者自己的司機清單（只給自己看）
```

**關鍵：授權的真相在 `users/{driverUid}/meta/access.bookkeepers`。**
記帳者能不能讀某司機的 `days`，最終由 **Firestore 安全規則**依這份清單判定，
不是靠前端。前端只是把清單畫出來。

## 3. 授權流程（邀請碼）

### 3.1 司機產生邀請碼 — `createInvite()`（sync.js）
6 碼隨機（撞碼重試 6 次），寫 `invites/{code}`，帶 `driverUid / driverName / exp`（30 天）。

### 3.2 記帳者兌換 — `redeemInvite(code)`（sync.js）
1. 讀 `invites/{code}`，用純函式 **`_claimBlock(d, myUid)`** 檢查是否可兌換：
   - 不存在／已過期／是自己的碼 → 擋
   - **一碼一用**：`claimedBy` 已是別人 → 擋（先兌換者贏；同一人重複兌換＝冪等放行）
2. 回填 `claimedBy / claimedName` 到邀請碼 → 這是「司機自動授權」的觸發點
3. 在自己名下寫 `linkedDrivers/{driverUid}`（記帳者的司機清單）

### 3.3 司機自動授權 — `processInviteClaims()`（sync.js）
司機端每次登入後（`onAuth` 延遲 1.5 秒）跑一次：
- 查自己產生的所有邀請碼，對每張用純函式 **`_shouldAuthorize(d, bk)`** 判斷：
  `有 claimedBy && 未 revoked && 尚未在授權清單` → 加進 `access.bookkeepers`
- 「自己產生的碼被兌換」＝已同意，所以**自動**加入、不用司機再按確認

> ⚠️ **司機必須「打開一次 App」讓 `processInviteClaims` 跑到**，記帳者才真正被寫進授權清單。
> 記帳者看不到資料的頭號原因就是這個（司機還沒開 App 完成授權）。

### 3.4 撤銷授權 — `removeBookkeeper(uid)`（sync.js，v263 修）
1. 從 `access.bookkeepers` 刪掉該記帳者
2. **撤銷持久化**：把該記帳者兌換過的邀請碼全部標 `revoked: true`
   - 若不標記，下次 `processInviteClaims` 會看到舊 `claimedBy` **又把他加回來＝撤銷無效**
   - `_shouldAuthorize` 因此加了 `!d.revoked` 條件

### 3.5 記帳者移除司機 — `unlinkDriver(driverUid)`（sync.js）
只刪記帳者自己的 `linkedDrivers` 清單項。**司機端的授權仍在**，需司機自行撤銷
（面板移除時的確認文案已講清楚，避免誤會）。

## 4. 記帳者端操作（bookkeeper.js）

底部彈出式面板（`#bk-sheet`），純 DOM，自帶樣式。

- **首頁 `renderHome()`**：兩區塊 —「授權我的記帳者」（司機視角）、「我協助記帳的司機」（記帳者視角）。
  進首頁時先 `processInviteClaims()`，再列 `listBookkeepers()` / `listLinkedDrivers()`。
- **司機檢視 `renderDriver()`**：`readDriverData(driverUid)` 讀 profile＋days＋commissions，
  依日期分組列每趟（時間／車資／付款別／抽成／叫車），每趟可「編輯抽成」。
  - **抽成累計小計卡（v267）**：頂端顯示「本月抽成（趟數／叫車）＋全部抽成」，
    回答「這個月幫這位司機記了多少」。純函式 `_summary(days, commissions, now)`：
    記帳者填的 `commissions` 優先於行程自帶值（**明確填 0 也優先**，用 `!=null` 判斷），
    `day.slice(0,7)` 切當月。
  - **讀取失敗**會顯示**真正的 Firestore 錯誤碼**（v266），並指出兩大主因：
    ① 司機沒開一次 App 完成授權；② 規則沒部署。
- **編輯抽成 `saveComm(tripId)`**：`writeCommission(driverUid, tripId, comm, disp)`
  寫 `users/{driverUid}/commissions/{tripId}`，即時更新快取重繪。

### 名字注入防護（v263）
所有 `onclick` **只帶 uid**（Firebase uid 為英數，安全），名字改用模組內 `_bks`/`_drivers`
查表（`_bkName`/`_drvName`）。因為 `esc()` 不跳脫單引號，名字含 `'` 原本可從 onclick 字串跳出。

## 5. 雙向即時同步

- **記帳者 → 司機**：記帳者寫 `commissions/{tripId}`；司機端 `onSnapshot` 訂閱自己的
  commissions 集合，變動時呼叫 `window.applyCommission(tripId, commission, dispatch)`
  把抽成合併回本機行程（sync.js 約 363 行）。司機不用重整就看到記帳者填的抽成。
- **司機 → 記帳者**：記帳者每次進司機檢視都重新 `readDriverData`（一次性快照，非即時訂閱）。

## 7. 安全模型（**務必讀**）

**安全根是 Firestore 安全規則，不在這個 repo（部署在 Firebase console）。**
前端所有檢查（`_claimBlock`/`_shouldAuthorize`/唯讀畫面）都只是 UX，繞得過。
真正擋「記帳者只能讀被授權司機的 days、只能寫 commissions」的是規則。

- 規則參考：`docs/記帳者-firestore規則參考.md`，核心是
  `isBookkeeper(driverUid)` = `get(.../meta/access).data.bookkeepers[request.auth.uid] != null`
- 規則沒部署／沒放行 → 整條授權＋讀取都會 `permission-denied`
  （連 `processInviteClaims` 查 invites、`readDriverData` 讀 days 都被擋）
- **我（AI）無法實測規則**，請務必用**第二個帳號＋Firebase Rules Playground**實測。

## 8. 純函式與測試（可回歸）

| 純函式 | 檔案 | 作用 |
|--------|------|------|
| `_claimBlock(d, myUid)` | sync.js | 邀請碼可否被兌換（一碼一用） |
| `_shouldAuthorize(d, bk)` | sync.js | 司機端是否自動授權（跳過 revoked） |
| `_summary(days, commissions, now)` | bookkeeper.js | 抽成累計小計（本月／全部） |

Playwright（scratchpad，容器重啟會消失需重建）：
- `bkcheck.js`：`_claimBlock`／`_shouldAuthorize` 邊界（撤銷持久化、一碼一用、名字注入）
- `bksummary.js`：`_summary` 11 項（本月／全部加總、commissions 優先、填 0 優先、
  空資料、跨年月、renderDriver 實際渲染小計卡），零 pageerror
- `desktopcheck.js`：記帳者模式判定／apply（原生 no-op、瀏覽器 wire＋toggle、review 藏 GPS）

## 9. 已知限制與待辦

- **Firestore 規則實測未完整驗證**（我無法測，需使用者用第二帳號＋Rules Playground）。
  目前線上疑似「記帳者確認授權後看不到司機資料」＝規則未部署/未放行的機率最高，
  v266 已讓面板顯示真正錯誤碼待回報確認。
- `readDriverData` **無分頁**：重度司機（大量 days）會慢、吃額度 → 之後可加分頁/日期範圍。
- 記帳者看到的司機行程是**一次性快照**（非即時訂閱）；抽成方向才是即時。
- 抽成小計目前只有「本月／全部」兩檔，未做任意月份選擇（可日後擴充）。
