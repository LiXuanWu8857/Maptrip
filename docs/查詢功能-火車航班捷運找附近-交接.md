# 查詢／提醒功能（火車・捷運・航班・找附近）— 功能與交接

**現況版本：v1.1.443**。給下一個 session 接手用：把「火車到站提醒／查詢、捷運到站提醒、
航班查詢、地圖 POI 圖層、找附近(便利商店/停車場…)」這一整組查詢類功能的檔案、資料來源、
金鑰機制、對外 API、血淚坑、測試、待辦一次列清楚。

> 一句話：火車/捷運/航班都走 **TDX**（交通部運輸資料流通服務），金鑰藏在**共用 Cloudflare
> Worker 代理**（全體使用者免申請、預設可用）；找附近(加油/停車/超商/醫院)走 **OSM Overpass**。
> 捷運到站落地點直接呼叫 `MaptripNav` 導航選單。

## 2. 資料來源與金鑰機制（火車/捷運/航班共用）

- **TDX**（`tdx.transportdata.tw`）是台灣唯一穩定免費的大眾運輸資料源，但**一定要金鑰**
  （OAuth2 client_credentials 換 bearer token，一天有效、快取）。Google 沒有火車/捷運到站公開 API。
- **共用 Cloudflare Worker 代理**：`https://maptrip-tdx.tumblestudio.workers.dev`
  - 金鑰藏在 Worker 伺服器端＋邊快取 → **全體使用者免自己申請金鑰、預設即可用**。
  - 路徑結構與 TDX 相同，Worker 內帶 token 轉發。
  - 前端判斷 `useProxy()`：沒填自己金鑰 → 走代理；填了 `maptrip_tdx={id,secret}` → 直連 TDX（進階）。
  - **部署/維護見 `docs/火車提醒-金鑰共用-Cloudflare-Worker.md`**。
  - ⚠️ **Worker 路徑白名單**：若 Worker 只放行 `/v3/Rail/*`，**航班 `/v2/Air/*` 與捷運 `/v2/Rail/Metro/*`
    會被擋** → 要在 Cloudflare 端讓 Worker 放行這些路徑（沙箱測不到，需實機驗）。
- **端點版本**（容易踩）：台鐵 TRA＝**v3**；捷運 Metro＝**v2**；航班 Air FIDS＝**v2**（v1 會 404）。
- **限流（429）**：各模組都有 `cooldownUntil`（退避 2 分鐘）＋快取，避免狂打。
  注意 `oneway.js/hotspots.js/nearby.js` 另外共用 OSM Overpass（與 TDX 無關，但同樣會被 per-IP 限流）。

## 3. 火車到站提醒（`train-alert.js` / MaptripTrain）

- **行為**：靠近火車站 **2km**（`RADIUS`）內，抓**前後 10 分鐘**（`WINDOW_MIN`）的到站列車，
  到站前 0–3 分「🚆 火車即將抵達！」、到站 -2–0 分「🚆 火車已抵達！」彈窗（`phaseOf`）。
- **模式** `maptrip_train_mode` ∈ `off`／`demo`（假班次預覽）／`live`（真 TDX）。**有內建代理 → 預設 live**。
- **流程**：`start()`（開機 4s 後＋設定變更）→ 每 30s `check()`：`loadStations`（快取 30 天）→
  `nearbyStations`（近→遠）→ 最近站 `loadTimetable`（當日時刻快取 6 小時，失敗負快取 5 分）→
  `windowTrains` 篩窗內 → 命中提醒階段且該班該階段沒跳過才 `showPopup`（`alerted` 去重）。
- **端點**：`/v3/Rail/TRA/Station`（站點）、`/v3/Rail/TRA/DailyStationTimetable/Today/{sid}`（當日時刻，
  空→退 `StationLiveBoard/Station/{sid}` 即時看板）。多種 v3 包裝/欄位名容錯（`parseTimetable`）。
- **設定面板** `openSettings`：off/demo/live 切換＋`details` 進階自填 TDX 金鑰＋「🔎 測試查詢（台北車站）」
  （`test()` 直接查 StationID `1000`，不必真的開到車站旁；防重複點擊＋限流提示）。
- **純函式（測試）**：`_parseHM/_minsUntil/_nearbyStations/_windowTrains/_phaseOf`。
- **黑盒子**：`__mtLog('train:...')`（stations n、tt today、liveboard、test err…）。

## 4. 捷運到站提醒（`metro-alert.js` / MaptripMetro）

- **為什麼跟火車分開**：捷運**沒有即時到站**（TDX 捷運只有時刻表），但捷運準點→時刻表≈實際到站。
- **核心＝自適應彈窗**（與使用者討論定案）：用「前後 5 分窗內有幾班車」判稀疏/密集，不用時鐘硬分尖離峰：
  - 窗內 **≤2 班＝稀疏**（離峰/深夜，錯過等很久）→ ✅ 主動彈窗（值得先去卡位）。
  - 窗內 **>2 班（`DENSE_N`）＝密集**（尖峰，隨時有車）→ 🔇 安靜（每 3 分跳一次沒鑑別度＝開車干擾）。
  - **末班車**（收班前）＝搭不到要叫車＝最強訊號 → 🔴 一律強提醒＋標「末班車」。
- **靠近門檻 `RADIUS`=1500m**（捷運站密、比火車近）。
- **營運商 `OPERATORS`=['TRTC','NTMC','TYMC']**（台北/新北環狀/桃園機捷）。
- **端點**（**v2**）：`/v2/Rail/Metro/Station/{Operator}`（站點含 GPS）、
  `/v2/Rail/Metro/StationTimeTable/{Operator}`（時刻表；欄位是 **DepartureTime** 不是 ArrivalTime，HH:MM）。
- **純函式**：`_parseHM/_minsUntil/_serviceToday/_buildIndex/_stationTrains/_decide/_nearbyStations/_lineColor`。
- 設定面板同火車（off/demo/live＋測試查詢「台北車站」TRTC）。黑盒子 `metro:...`。

## 5. 航班查詢（`flight.js` / MaptripFlight）

- **用途**：①☰「✈ 航班查詢」獨立浮動視窗（`openLookup`）；②**預約表單**「航班查詢帶入」回填出發/目的地。
  Phase 1 **只做查詢，不做延誤提醒**。**只桃園 TPE**。
- **端點（v2）**：`/v2/Air/FIDS/Airport/Departure|Arrival/{TPE}`（官方 swagger；v1 404）。60 秒快取省額度。
- **對外** `lookup(flightNo, dir)`：`dir ∈ 'departure'(送機) | 'arrival'(接機)` → `Promise<正規化物件|null>`
  （航空公司中文名/航廈文字/時刻/狀態中文/登機門/對向機場）。
- **寬鬆比對**（血淚）：`_key` 去前導零（`BR0225==BR225`）、`_match` 比對 `AirlineID+FlightNumber`＋
  CodeShare＋純數字尾數。`_airZh` 內建常見航空中文名；`terminalText` 航廈→「第X航廈」；`_statusZh` 狀態中譯。
- **純函式**：`_norm/_key/_match/_pick/_statusZh/_hhmm/_fullNo/_fidsPath`。

## 6. 向量地圖 POI 圖層（`transit.js` / MaptripTransit）

- **只在向量（MapLibre GL）引擎**：Positron 底圖乾淨、預設不畫 POI，這裡把「開車有用」的幾類從同一份
  OpenMapTiles 向量圖磚（`poi` / `aerodrome_label` 圖層）挑出來疊回並標名稱。**不是**叫 API，是渲染既有圖磚。
- **分類**：捷運（railway+subway，方形 M）／火車（railway 非 subway，圓形火車）／機場（飛機）／
  加油站（綠油槍）／停車場（藍 P）。各類 `minzoom` 門檻不同（`_specs`）。
- **圖示＝canvas 即時畫 → `gl.addImage`**（比照 gl-compat 的台灣公路盾牌做法）。
- **點任一圖示 → `onNavigate(name, lat, lng)`**（app.js 接 `MaptripNav.open`）。
- **純函式**：`classify(cls,subclass)`、`_specs(src)`（filter/minzoom 驗證）、`draw`（各圖示）。
- ⚠️ 這是**標準/向量引擎差異**的典型：標準 Leaflet（Google 圖磚）本來就有 POI，不需這層；GL 才裝。

## 7. 血淚坑 / 設計要點
1. **金鑰只在 Worker**：前端永遠不帶 TDX key（除非使用者自填走直連）。改資料源先確認 Worker 路徑白名單放行。
2. **端點版本別搞混**：TRA=v3、Metro=v2、Air=v2。用錯版號＝404。
3. **捷運用 DepartureTime 不是 ArrivalTime**（TDX 捷運時刻表欄位）。
4. **捷運自適應是刻意的**：尖峰故意不彈窗（交給找客熱區）。別「好心」改成每班都提醒＝變開車干擾。
5. **航班號寬鬆比對**：司機會打 BR225 或 BR0225 或只打數字，`_key/_match` 都要吃得下。
6. **限流退避＋快取**：三支都有 429 cooldown；測試查詢防重複點擊。沙箱擋 TDX/Overpass，**連線類只能實機驗**。
7. **POI 圖層只 GL 有**：transit.js 標準引擎不裝（Leaflet 自帶 POI）。

## 8. 測試（Playwright/node，沙箱；容器重啟會消失需重建）
- **純函式可直接 node 測**（不碰網路）：
  - train：`_parseHM/_minsUntil/_nearbyStations/_windowTrains/_phaseOf`（窗內篩選、提醒階段、近站排序）。
  - metro：`_serviceToday/_buildIndex/_stationTrains/_decide`（稀疏彈窗/密集安靜/末班車強提醒判斷）。
  - flight：`_key/_match`（BR225==BR0225、CodeShare、純數字）、`_statusZh/_hhmm/terminalText/airlineName`、`_pick`（多筆取最早）。
  - transit：`classify`、`_specs`（filter/minzoom）。
- **連線類**（TDX/Overpass 實打）沙箱做不到 → 用 route-mock 餵假 JSON 測解析，真連線**實機驗**（黑盒子看 `train:/metro:/nearby:` log）。
- 跑法：`env -u HTTPS_PROXY -u HTTP_PROXY -u https_proxy -u http_proxy NODE_PATH=/opt/node22/lib/node_modules /opt/node22/bin/node <測試>.js`。

## 9. 待辦 / 可改進

## 10. 給接手者的一句話
查詢三兄弟（火車/捷運/航班）都是「TDX＋共用 Worker 代理」同一套路：`useProxy()` 決定代理或直連、
token/快取/429 退避都雷同，純函式負責解析與判斷。**改資料源**先顧 Worker 白名單與端點版號；
**POI 圖示**在 transit.js（只 GL）；**找附近**在 nearby.js（Overpass，另見搜尋 doc）。改完照慣例補
Playwright 測試、零 pageerror 再部署。
