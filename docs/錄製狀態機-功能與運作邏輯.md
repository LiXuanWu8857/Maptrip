# Maptrip 錄製狀態機（Recorder）— 功能與運作邏輯

> 對象：`js/recorder.js`（v1.1.259 起，`MaptripRecorder`）與 `js/app.js` 中仍保留的錄製相關程式。
> 這是全專案**耦合最深、動到會賠錢（掉行程）**的一塊；使用者又正在用。本文說明它**做什麼**、
> **怎麼運作**、**為什麼這樣切**，供日後維護與再重構。

---

## 1. 功能總覽

把「司機從上車到下車」的一趟行程，從 GPS 訊號變成一筆存好的紀錄，並在過程中撐住
鎖屏方塊 / 浮動視窗 / 螢幕常亮 / 當機復原。核心是一台狀態機：

```
       startTrip / widgetStart / 鎖屏「開始」
  閒置 ───────────────────────────────────▶ 記錄中
   ▲                                          │
   │   endTrip / 鎖屏「結束」/ 浮窗「結束」      │
   └──────────────────────────────────────────┘
              （落盤 → 補車資 → 貼路）
```

- **開始**：`startTrip`（App 內鈕）、`widgetStart`（鎖屏方塊，GPS 未定位時排隊）→ `beginRecording`。
- **記錄中**：`onGpsUpdate`（在 app.js）每筆定位延伸折線、每秒存一點、每 30 點即時貼路；
  `saveActiveTrip` 定期把進行中軌跡存本機（當機復原用）；`widgetHeartbeat` 替鎖屏方塊續命。
- **結束**：`endTrip` → 立即落盤（`saveTripFinal`，fare=0，先確保不掉）→ 依來源叫車資對話框
  （App 內 `showFareDialog` / 浮窗數字鍵盤 `saveFloatFare`）→ `finalizeSavedTrip` 補車資＋貼路＋重畫。
- **復原**：開機 `restoreActiveTripIfAny` 若發現未結束的暫存，12 小時內自動接回繼續記錄，
  逾時則轉存成完成趟（金額可補填）。

## 2. 模組邊界（為什麼這樣切）

錄製區塊天生是「活狀態 ＋ 操作地圖/DOM ＋ 原生外掛副作用」的糾纏體，`activeTrip`
在 app.js 有 **50+ 處**引用、十多處在錄製函式**之外**（initMap 事件、snapLiveRoute、
resyncLiveLine、updateTopBar、refreshAfterSync、retrySnapBacklog、boot…）。因此採**最小風險切法**：

### 2.1 搬進 `MaptripRecorder` 的（生命週期＋復原＋原生介面＋GPS 監看啟動）
`startGpsWatch / startNativeGpsWatch / startSimulation / runSimulation / restartSimulation / onGpsError`、
`startTrip / beginRecording / endTrip`、`requestWakeLock`、
`handleWidgetUrl / widgetStart / consumePendingWidgetCmd / consumePendingWidgetCmdRetry / widgetHeartbeat`、
`finalizeSavedTrip / saveActiveTrip / clearActiveTrip / restoreActiveTripIfAny / saveFloatFare / saveTripBackground`。
（共 21 個公開函式，app.js 留同名薄包裝轉呼叫，呼叫端含 HTML onclick／initMap 事件**零改動**。）

模組**私有**狀態：`simTick / simTimer / nativeWatcherId / lastHeartbeat / _lastActiveSave /
pendingFareTrip / timerTick / ACTIVE_KEY`（原本散在 app.js，只有錄製用到，整組搬入）。

### 2.2 **刻意留在 app.js** 的（繪圖而非狀態機）
- **`onGpsUpdate` 的「逐點收錄」子區塊**：與地圖手勢狀態 `_mapZooming / _mapTouching /
  _lineResyncPending`、即時折線 `activePolyline.addLatLng`、品質閘門 `MaptripGeoGate` 綁死，
  是**繪圖**與 GPS 熱路徑，搬走反而增加注入面與風險 → 不動（GPS 熱路徑零改動）。
- `activeDist`（增量距離，refreshRecBanner 也用）、`snapLiveRoute` / `resyncLiveLine`
  （即時折線重建，讀 activePolyline/手勢狀態）、`saveTripFinal`（畫線＋落盤，讀 todayTrips/allMapLayers）。

### 2.3 共用活狀態**續留 app.js**、經 `init(ctx)` 注入（getter 呼叫時才讀）
`activeTrip / activePolyline / currentPos / wakeLock / todayTrips / allMapLayers /
pendingWidgetStart / activeSnapPending`。**這是關鍵**：讓 app.js 那十多處外部讀取 `activeTrip`／
`activePolyline` 全部**零改動**（它們仍讀 app.js 的 `let`），模組則透過 `ctx.getActive()/setActive()`
等存取器讀寫同一份來源。getter 而非快照 → 之後雲端同步把 `todayTrips` 換成新物件，模組仍拿到最新。

### 2.4 執行期由 window 取用的全域函式（app.js `function` 宣告皆全域，直接呼叫）
`goHome / setAutoFollow / refreshRecBanner / toast / dbg / liveAct / floatWin / isNative /
saveTripFinal / snapToRoads / drawTripLine / saveTodayToStorage / _pushCommission / updateTopBar /
retrySnapBacklog / renderTripSheet / _cleanTrace / calcTotalDist / activeDist / snapLiveRoute /
showFareDialog / businessDayKey / loadTrips / saveTrips / serializeTrip / setGpsBadge`、
以及 `MaptripSync / MaptripGeoGate`。

## 3. 注入契約（`MaptripRecorder.init`）

app.js `initMap` 內、`restoreActiveTripIfAny/startGpsWatch` 之前呼叫：

```js
MaptripRecorder.init({
  testMode: TEST_MODE_ON,          // 決定 ACTIVE_KEY（maptrip_active / _test）
  getMap: () => map,
  getActive: () => activeTrip,             setActive: v => { activeTrip = v; },
  getActivePolyline: () => activePolyline,  setActivePolyline: v => { activePolyline = v; },
  getCurrentPos: () => currentPos,
  getWakeLock: () => wakeLock,              setWakeLock: v => { wakeLock = v; },
  setPendingWidgetStart: v => { pendingWidgetStart = v; },  // widgetStart 排隊用；onGpsUpdate 讀/清
  setActiveSnapPending: v => { activeSnapPending = v; },    // beginRecording 歸零；onGpsUpdate/snapLiveRoute 讀
  getTodayTrips: () => todayTrips,          // finalizeSavedTrip 用 id 重新定位
  getAllMapLayers: () => allMapLayers
});
```

## 4. 幾個「勿踩」的運作細節

- **先落盤再問車資**：`endTrip` 一結束就 `saveTripFinal(fare=0)`，之後 App 被殺也不掉趟；
  車資/貼路用 `finalizeSavedTrip` **以行程 id 重新定位**寫回（不能靠物件同一性，貼路慢、期間
  可能被雲端同步換成新物件，否則寫到孤兒物件遺失）。
- **鎖屏排隊**：背景被喚醒常還沒定位，`widgetStart` 先設 `pendingWidgetStart`，下一筆 GPS 進來
  （app.js `onGpsUpdate` 開頭）才 `beginRecording`。
- **續命節流**：`widgetHeartbeat` 至少每 2 秒一次（過期 6 秒），前景 3 秒一跳、背景由 GPS 回呼觸發。
- **貼路失敗**：`finalizeSavedTrip` 走 `_cleanTrace` 清飄移群再重畫，並 60 秒後 `retrySnapBacklog(2)`。
- **wakeLock**：系統熄屏/切 App 會自動釋放（release 事件把它設 null），回前景 `visibilitychange`
  （留在 app.js）看到記錄中且 wakeLock=null 就重取。

## 5. 測試

`scratchpad/rectest.js`（Playwright，stub map／全域）：**31 項全過、零 pageerror**。涵蓋
薄包裝存在、start→begin（狀態/DOM/續命暫存/LiveActivity）、記錄中重按被擋、endTrip（清狀態/落盤/
車資對話框/清暫存）、widgetHeartbeat 不丟錯、無定位 widgetStart 排隊、restore 接回、restore 逾 12h
轉存、浮窗結束→saveFloatFare→finalize、finalize 貼路成功（trim 座標＋重畫）與失敗（清飄移群）。
載入方式：TripStore.init 掛住讓 boot 不執行→只留定義；依 index.html 順序載全部模組（app.js 頂層
會呼叫 MaptripShot.init/MaptripReplay.init）；再以測試 ctx 重新 `MaptripRecorder.init` 驅動。
