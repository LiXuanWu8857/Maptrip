# 車資輸入（現金／刷卡／其他）— 功能與交接

**現況版本：v1.1.442**。給下一個 session 接手用：把「每趟車資怎麼輸入、現金/刷卡怎麼分流、
抽成/叫車費/小費、以及事後怎麼編輯」這一整塊的檔案、資料模型、對外 API、接點、血淚坑、
測試、待辦一次列清楚。

> 一句話：行程結束 → 彈「行程完成」對話框輸入金額、按**現金／刷卡／其他** → 寫進該趟
> `fare/paymentMethod`，再經 `finalizeSavedTrip` 落盤＋貼路＋上雲。事後可從清單每趟的
> ✏ 鈕改金額/付款。所有「刷卡/現金/總計」統計都由 `util._fareStats` 單一算出。

## 2. 資料模型（每趟 trip 上的欄位）
| 欄位 | 型別 | 說明 |
|---|---|---|
| `fare` | number | 車資（主金額）。0＝未填 |
| `paymentMethod` | `'cash'`／`'card'`／`'voucher'`／`'other'` | 付款方式。`'voucher'`＝紙本簽單（v1.1.440，現金鈕長按切換；單獨統計、計入總計）。`'other'`＝非載客（自用等），不算營收、`workMs` 也排除 |
| `label` | string | 只有 `'other'` 用：備註名稱（例「騎腳踏車」）；轉回現金/刷卡會**清空** |
| `commission` | number | 抽成（通常兩天後才知道，完成當下不問、歷史批次補） |
| `dispatch` | number | 叫車費（固定 `DISPATCH_FEE=10`，用切換按鈕開/關） |
| `tip` | number | 小費/加收（同一筆可另收一筆） |
| `tipMethod` | `'cash'`／`'card'`／`''` | 小費的付款方式（可與主車資不同，例：刷卡車資＋現金小費）；tip=0 時為 `''` |

> **統計口徑（`util._fareStats`）**：`total`＝Σfare＋Σtip；`voucher`＝簽單車資（有才顯示）；`card/cash` 依各自的
> `paymentMethod`／`tipMethod` 分流。`'other'` 的 fare 不計入 card/cash（它不該有 fare）。

## 3. 三個輸入/編輯流程

### 3.1 行程完成 → 新車資（`fare-dialog.js showFareDialog`）
1. `endTrip` 時該趟已先落盤（無金額）→ 彈 `#fare-dialog`，顯示起訖/時間/里程。
2. 預設：**叫車費「有」$10**（`_setFareExtra(0, DISPATCH_FEE)`，沒叫車費再點一下關）、小費 0 現金、
   **抽成欄隱藏**（`_showCommissionField(false)`，完成當下不問）。
3. 按鈕：
   - **現金** → `save(金額, 'cash')`；**長按現金鈕**切換成「紙本簽單」→ 單擊存 `save(金額, 'voucher')`
     （`bindCashButton`，長按後放手的 click 忽略；編輯對話框同樣支援）
   - **刷卡** → `save(金額, 'card')`
   - **其他** → `prompt` 輸入名稱 → `save(0, 'other', name)`
4. `save()` 立即關對話框 → `finalizeSavedTrip(trip, fare, pay, label, commission, dispatch, tip, tipMethod)`
   （車資先存，貼路在背景補）。

### 3.2 `finalizeSavedTrip`（recorder.js）——車資落地的唯一出口
- `apply(t)` 寫 `fare/paymentMethod/commission/dispatch/tip/tipMethod/label` 到 trip（＋記憶體中同 id 的那筆）。
- `saveTodayToStorage()`（內含雲端同步）→ 車資先存。
- `commission||dispatch` → `_pushCommission(id,...)` 上雲 `commissions/{tripId}`。
- 非 `'other'`＋有上車點 → `contributeHotspot`（共享熱點 count +1）。
- 之後 `snapToRoads` 貼路（成功才壓 coords 頭尾）——**與金額無關，貼路失敗不影響車資**。

### 3.3 事後編輯（`app.js editFare` 今日 / `editHistoryFare` 歷史）
- 清單每趟右側 ✏ 鈕（無金額時顯示「＋金額」）→ 開同一個 `#fare-dialog`，標題改「編輯」。
- 載入該趟現值：`input.value=fare`、`_setFareExtra(commission,dispatch)`、`_setTip(tip,tipMethod)`、
  `_showCommissionField(true)`（**編輯時可改抽成**）、「其他」鈕變「取消」。
- 存檔 `saveEdit(pay)`：寫回 trip → `saveTrips`／`saveTodayToStorage` → `_pushCommission` → 重繪。
  - **歷史編輯用 `trip.id` 定位**（避免期間雲端同步併入新趟造成索引位移）；若那趟也在今日記憶體，
    `todayTrips` 內同 id 也要同步更新（否則下次 `saveTodayToStorage` 合併用舊值蓋回）。
  - 轉成付費（非 other）→ 清 `label`。

### 3.4 其他入口
- **浮動視窗/Android**：`saveFloatFare(fare, paymentMethod, dispatch)` → `finalizeSavedTrip(..., 0 抽成, dispatch)`。
- **客人取消收款**（`cancel-fee.js`）：一鍵 **$40 刷卡**、`label='客人取消'`、`cancelFee:true`、無座標，走 `saveTripFinal`。

## 5. 血淚坑 / 設計要點（勿隨意動）
1. **`finalizeSavedTrip` 是車資落地的唯一出口**：完成、編輯、浮窗、取消收款都收斂到它（或 editFare 的 saveEdit）。
   要改「車資存法／上雲」只改這裡，別各自為政。
2. **歷史編輯用 `id` 不用索引**：同步隨時併入新趟 → 索引會位移。且「今日的趟」要同時更新記憶體 `todayTrips`，
   否則 `saveTodayToStorage` 合併用舊值蓋回（血淚）。
3. **抽成完成當下不問**：抽成常兩天後才知道 → `showFareDialog` 隱藏抽成欄，改在歷史批次補
   （`openCommissionBatch`）。編輯對話框才顯示抽成欄。
4. **叫車費預設「有」$10**：`showFareDialog` 用 `_setFareExtra(0, DISPATCH_FEE)`；沒叫車費要再點一下關。
   編輯舊趟則照該趟原值。金額改 `fare-dialog.js` 的 `DISPATCH_FEE`。
5. **小費付款方式可與主車資不同**：`tipMethod` 獨立分流（刷卡車資＋現金小費），`_fareStats` 已處理。tip=0 時 `tipMethod=''`。
6. **`'other'` 不是付費**：不算 card/cash/營收、`workMs` 排除、清單用 `_otherTag` 顯示 `label`。轉成付費要清 `label`。
7. **統計單一來源＝`_fareStats`**：今日摘要、歷史日/月、月結、記帳者全走它（記帳者另有 `fareOverride/payOverride` 覆蓋，見記帳者 doc）。
   新增「加收項目」記得同時進 `_fareStats` 與 `_extraTag`，否則總計對不上標籤。
8. **記帳者可覆蓋車資/付款**：寫 `commissions/{tripId}` 的 `fareOverride/payOverride`，司機端 `applyCommission` 套用
   （需司機開 `allowFareEdit`）。改車資輸入時注意別和覆蓋邏輯打架。

## 6. 測試（Playwright/node，沙箱；容器重啟會消失需重建）

- `util`：`_fareStats`（現金/刷卡/總計、小費分流、other 不計）、`_payTag/_otherTag/_extraTag` 字串。

## 7. 待辦 / 可改進
- 「其他」用 `prompt()` 輸入名稱（陽春）；可改成下拉常用項（自用/加油/保養…）。
- 小費/加收目前只有一筆；若要多筆加收需改資料模型（陣列）。
- 叫車費固定 $10 寫死（`DISPATCH_FEE`）；若各平台不同可做成可設定。
- 車資輸入本身沒有「快速金額」鈕（常見跳錶金額一鍵帶入）——可加速輸入。
