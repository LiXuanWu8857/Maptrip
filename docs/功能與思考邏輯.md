## 1. 整體架構

**是什麼**：Capacitor 6 混合 App。iOS 原生殼（WKWebView）**遠端載入** GitHub Pages 網頁
`https://lixuanwu8857.github.io/Maptrip/`。

**思考邏輯**：
- 選遠端載入而非把網頁打包進 App → **改網頁 code 不用重新打包、重簽 App**（免費開發者帳號憑證只有 7 天，能少接電腦就少接）。
- 沒有自己的後端伺服器（Serverless）：省錢、免維運。後端角色由免費服務頂替：
  - **GitHub Pages**＝靜態網站主機
  - **Firebase Auth + Firestore**＝登入 + 雲端資料庫（唯一像後端的角色）
  - **OSRM**＝貼路、**Overpass / Nominatim**＝地名/場所、**Google 圖磚**＝底圖
- 前端純 HTML/CSS/原生 JS，**無框架**（減少體積與記憶體，WKWebView 記憶體很吃緊）。

**檔案地圖**：
| 檔案 | 職責 |
|---|---|
| `index.html` | 殼＋開機守護腳本（黑盒子、防迴圈、看門狗、崩潰偵測、引擎選擇） |
| `js/app.js` | 主程式（~3900 行）：行程、地圖、記帳、歷史、回放、截圖 |
| `js/store.js` | `TripStore`：IndexedDB 儲存層 |
| `js/sync.js` | `MaptripSync`：Firebase 登入 + Firestore 同步 |
| `js/finance.js` | `MaptripFinance`：收支報表 + 分析（含上車熱點×時段） |
| `js/hotspots.js` | `MaptripHotspots`：找客熱區 |
| `js/gl-compat.js` | MapLibre GL 的 Leaflet 相容層 + 台灣路牌 |
| `js/bookkeeper.js` | 記帳者模式 |
| `sw.js` | Service Worker：離線快取 + 版本控制 |
| `native/*.swift` | Live Activity、CarPlay、背景復原（Xcode 專案是複本，改了要提醒使用者換入） |

## 2. 行程記錄（核心）

**是什麼**：手動「開始／結束」記錄一趟載客，記時間、里程、GPS 軌跡。

**思考邏輯**：
- **自動彈窗已停用**（`AUTO_PROMPTS=false`）：自動偵測「開始/結束」誤判率高，改回司機手動控制最可靠。
- **背景 GPS**：`@capacitor-community/background-geolocation`，鎖屏、切到導航 App 也持續收點。
- **GPS 品質閘門**：精度 > 40m、瞬移 > 50m/s（≈180km/h，不可能）的點**不記錄**——源頭擋掉髒資料，比事後清理省事。
- **先落盤再問車資**：`endTrip()` 一結束就先存一筆 `fare=0` 到 IndexedDB。**從此這趟就安全了**，即使車資輸入前 App 被系統砍掉也不會遺失。車資、貼路都用「更新」方式事後補。
- **行程被砍自動接回**：進行中的行程暫存 `ACTIVE_KEY`，App 被砍重開會自動接回繼續記。

**關鍵函式**：`startTrip()`、`endTrip()`、`saveTripFinal()`、`finalizeSavedTrip()`、`restoreActiveTrip()`
**行程物件**：`{ id, startTime, endTime, coords[], totalDist, fare, paymentMethod, commission, dispatch, label, roadCoords }`；`coords[0]`＝上車點。

## 3. 貼路 Snap + 三重防假路線

**是什麼**：把鋸齒狀的原始 GPS 軌跡「貼合」到真實道路上，畫出漂亮路線。

**思考邏輯**：
- 用 OSRM 公開伺服器 `/match`；點太多會被 `TooBig` 拒 → **自適應降階取樣 95→60→40→25**，逐級縮小。
- **2026-07 起連 25 點也常被拒＝伺服器收緊** → 後備走 `/route`，用取樣點當途經點。
- 貼路是外部服務，會回傳「假路線」（繞一大圈的鬼畫符）。**三重防線**：
  1. `_dropSpikes`：剔除孤立飄點（繞行比 > 2.5 且多繞 60m）
  2. `_snapSane`：長度檢查（match 允許 1.4×+500m；route 更嚴 1.2×+200m），超過就判定假路線丟棄
  3. `tripPath()`：顯示層最後防線，`roadCoords` 超長就不顯示
- `healBogusRoads`：**每次開機掃描修復**既有假路線。
- `slimTripForStorage`：在同步入口**剝除假路線**——否則合併評分會讓假路線永遠贏、造成同步無限來回。
- 貼路成功後 coords 壓縮成頭尾（**原始軌跡不可復原**，省空間）。失敗重試上限 `_snapN`＝15 次。
- 失敗 toast 已隱藏（只在診斷模式顯示，記進黑盒子）——司機不需要看到技術錯誤。

**關鍵函式**：`snapToRoads()`、`_sampleTrack()`、`_dropSpikes()`、`_snapSane()`、`healBogusRoads()`、`slimTripForStorage()`

## 4. GPS 飄移群清理

**是什麼**：都市峽谷反射、停紅燈怠速會產生「來回鋸齒／小圈」飄移群，把它們收乾淨。

**思考邏輯**：
- 為什麼不能只刪單點：飄移常常是一「叢」。`_dropSpikes` 用**視窗式（往前看 4 點）**收掉整叢。
- 判準（要同時成立才刪，避免誤殺真實轉彎）：繞行 > 2.5× 且多繞 60m，且（端點 < 35m ＝甩回原地 **或** 垂距 apex > 端距 2× ＝尖刺），並要求「第一個中間點自己就偏離 > 15m」避免連坐正常直行點。
- 真實繞街廓/轉彎（有前進、apex ≈ 端距）**不會被誤刪**。
- `_cleanTrace`：迭代 4 趟；安全閥＝**≥25 點才防過度清理**。
- 貼路失敗時（OSRM 現況常拒）在 `finalizeSavedTrip`/`retrySnapBacklog` 的失敗分支就清理原始軌跡並重畫。
- `healZigzagTraces`：開機一次性清既有未貼路趟（`maptrip_zigfix` 版本旗標，不受 `_snapN` 上限限制）。

**關鍵函式**：`_dropSpikes()`、`_cleanTrace()`、`_perpM()`（垂距）、`healZigzagTraces()`

## 5. 地圖顯示

### 5.1 雙地圖引擎
- **標準**＝Leaflet 1.9.4 + leaflet-rotate（Google 圖磚，`keepBuffer:0` 畫面外圖磚立刻釋放省記憶體）
- **向量（Beta）**＝MapLibre GL 4.7.1，經 `js/gl-compat.js` 相容層，**app.js 不分引擎**（同一套 code 兩種引擎都能跑）。
- 引擎選擇（index.html loader）：**App 內預設向量**（`maptrip_gl='0'` 才關）、**瀏覽器預設標準**（Safari 分頁記憶體上限低，向量會崩）。
- `mt_glfail`（時間戳）＝GL 失敗後走標準 3 小時；`mt_glfail_reason` ∈ {crashloop, reloadloop, loadfail, jsfail}，開機 toast 告知使用者。

### 5.2 地圖朝車頭
- 預設開；**羅盤（靜止時）＋GPS 方向（行駛時）雙來源**。羅盤 60Hz 會抖 → 節流＋死區 2.5°/3°（見穩定性章）。

### 5.3 折線脫鉤修正（v247，標準地圖）
- leaflet-rotate 手勢式「縮小＋旋轉」後 SVG 折線幾何有時沒重算、整條飄離底圖（點/標記正常，只有線脫鉤）。
- `redrawAllLines()` 在 zoomend/moveend/去抖 rotate 後**強制以目前投影重畫所有折線**。GL 模式無此問題自動略過。

### 5.4 今日圖層三態 `_todayMode`
- `normal`／`hidden`（歷史檢視時整組隱藏）／`solo`（今日單趟：線 0.12 淡化、**點整組隱藏**）。
- **GL 陷阱**：MapLibre 每次 render 會重寫 marker 的 `style.opacity` → 隱藏 marker 必須用 `display:none`（shim `Marker.setOpacity(0)` 已改為 display）。

**關鍵函式**：`redrawAllLines()`、`drawTripLine()`、`drawGapLine()`、`_todayPane()`

## 6. 鎖定畫面 / 動態島 / 浮動視窗

**是什麼**：不用打開 App 也能看到即時時間/里程、一鍵開始/結束。

**思考邏輯**：司機開車時 App 常在背景（跑導航），需要在鎖定畫面就能操作。

- **Android**：浮動視窗對應（`native/android/FloatingWindowPlugin.java`），浮窗數字鍵盤輸入車資（`saveFloatFare`）。

## 7. 記帳：車資 / 付款 / 叫車費 / 抽成

### 7.1 車資與付款方式
- 每趟填車資；付款＝**現金 / 刷卡 / 其他**。「其他」可填備註 label（如「騎腳踏車」），改回現金/刷卡會清 label。
- 「其他」不計入營收，但時間照算進工作時間。

### 7.2 叫車費切換（v249；v250 預設有）
- **思考邏輯**：多數趟是叫車來的、金額固定，不該每趟打字。
- 改成**單一切換按鈕** `toggleDispatch()`：開＝`DISPATCH_FEE`（10 元）、關＝0。
- **v250 起行程完成對話框預設「有」10 元**（`showFareDialog` 用 `_setFareExtra(0, DISPATCH_FEE)`），沒叫車費再點一下關掉。
- 載入舊趟編輯時，若該趟 dispatch > 0 則沿用該趟原本金額（不強制改成 10）。

### 7.3 抽成延後 + 批次編輯（v249）
- **思考邏輯**：**抽成通常兩天後才知道**，所以行程完成當下問抽成沒意義。
- 完成對話框**隱藏抽成欄**（`_showCommissionField(false)`）；編輯對話框仍顯示。
- 歷史每日標題新增「抽成」鈕 → 開底部 sheet 列出當日各趟（時間／車資）→ 各自填不同抽成 → 一次「全部儲存」。
- 逐筆 `_pushCommission()` 上雲、`syncDays()` 同步。純 DOM 面板（`#commission-sheet`）。

**關鍵函式**：`showFareDialog()`、`editHistoryFare()`、`_readFareExtra()`/`_setFareExtra()`、`toggleDispatch()`、`openCommissionBatch()`/`saveCommissionBatch()`、`_pushCommission()`

## 8. 收支報表與分析

**檔案**：`js/finance.js`（`MaptripFinance`）

### 8.1 收支（`io` 分頁）
- 月營收（排除「其他」）、淨收入＝**營收 − 抽成/叫車 − 支出**、現金/刷卡拆分。
- 支出 CRUD（`localStorage maptrip_expenses`），7 類（加油/保養/靠行/保險/停車過路/餐飲/其他）。

### 8.2 分析（`an` 分頁）
- 每小時營收（24 條）、每星期營收（7 條）、每小時淨收入、每公里營收、平均每趟、最賺時段。
- **上車熱點 × 時段（v248）**：把每趟 `coords[0]` 上車點聚成 300m 網格，**跨全部歷史**（不受月份篩選，因熱點需要量）＋一天切 **8 段**（清晨/早尖峰/上午/中午/下午/晚尖峰/晚間/深夜，深夜跨午夜）。
  - 呈現「各時段最熱上車點」（回答**哪個時段在哪個地點人最多**）與「上車熱點排行」（趟數／均車資／尖峰時段）。
  - 地名用 **Nominatim reverse**（`zoom=16&accept-language=zh-TW`）非同步補上，快取在 `localStorage maptrip_geocache`（key＝小數 3 位；空字串也快取避免重打），每筆間隔 1.1 秒、已快取者不等待；離線/失敗顯示「未命名地點」但趟數統計照常。

**純函式（供測試）**：`_analyzePickups`、`_bucketIndexOf`、`_pickName`

## 9. 找客熱區（即時當前時段）

**檔案**：`js/hotspots.js`（`MaptripHotspots`）

**是什麼**：FAB 開啟，告訴司機「現在附近哪裡好叫客」。

**思考邏輯**：
- **為什麼不串 Google 即時人潮**：Google「熱門時段」從未開放 API，只能靠違反 ToS、隨時會壞的爬蟲，在 WKWebView 遠端網頁不可能穩定跑。
- **v249 起優先即時**（使用者要的即時感）：`buildHistoryNow` 直接讀當下位置與時間，只取「**當前時段（同 8 段桶）＋附近 2km**」的歷史上車點，就地 350m 聚類、近期加權排名，**秒出免等網路**。
- 只有這個時段**還沒有歷史**時，才退回 Overpass 附近場所估算（車站/百貨/夜市/醫院…依類型×時段加權）。
- 面板依 `meta.mode` 切文案／顯示趟數。

**純函式（供測試）**：`_buildHistoryNow`、`_bucketOf`

## 10. 歷史 / 預覽 / 回放 / 截圖

- **歷史行程**：月/日收合清單；每日顯示趟數、里程、營收、工作時長；可設休息時間。
- **單趟預覽（今日與歷史）**：一律切**白色無標示底圖**（CartoDB nolabels，深色模式深色版），退出還原。今日路線藍色、歷史黑色。左右滑切趟。有截圖鈕。
- **回放**：今日或歷史日，鏡頭跟隨、速度調整；回放中所有自動運鏡讓路。
- **截圖**：單趟/全日，含日期時間、金額、「其他」顯示備註；分享／儲存合一。

**關鍵函式**：`renderHistorySheet()`、`showHistoryTrip()`、`previewDay()`、`replayDay()`、`deleteHistoryTrip()`

## 11. 雲端同步與記帳者模式

**檔案**：`js/sync.js`（`MaptripSync`）、`js/bookkeeper.js`

**思考邏輯**：**本機是主來源，雲端只是備份/同步副本**。未登入或沒設 Firebase 時整個功能安靜停用，App 照常運作。

- **登入**：Firebase Auth（Google），持久化登入。首次登入要求顯示名稱（記帳者/司機互相辨識）。
- **合併規則**：以**日期**為單位，同一天內以**每趟 id 去重**，多裝置不互相覆蓋。評分取較新/較完整者。
- **記憶體風暴修正**：`onSnapshot` 只合併 `docChanges()` 變動的日子（首快照才全量）——否則每次雲端一動就全量重合併會爆記憶體。
- **Firestore 結構**：`users/{uid}/days`（行程）、`commissions/{tripId}`（抽成，記帳者可寫）、`meta/access.bookkeepers`、`invites/{code}`。
- **記帳者模式**：邀請碼授權；記帳者唯讀行程、可編抽成；雙向即時同步（司機端訂閱 commissions → `applyCommission` 合併）。

**關鍵函式**：`MaptripSync.syncDays()`、`writeCommission()`、`applyCommission()`、`processInviteClaims()`

## 12. 儲存層

**檔案**：`js/store.js`（`TripStore`）

**思考邏輯**：localStorage 只有 ~10MB 且滿載會**靜默存不進去**；IndexedDB 數百 MB 一勞永逸。

- **記憶體快取為同步讀寫來源**（介面與舊 localStorage 用法等價：`loadTrips`/`saveTrips`），呼叫端不需改寫成 async。
- 寫入以「日」為單位**髒檢查**後**非同步串行**寫回 IndexedDB（順序保證）。
- **開機聯集合併**：只要 localStorage 還有資料，每次開機都以趟 id 為鍵做聯集（永不減少），涵蓋「搬移被 reload 打斷」「IDB 開太慢退回 LS」「系統清掉 IDB」三種情況，不會缺趟。
- **墓碑過濾**：使用者刪除的趟 id 記在 `maptrip_deleted`，合併時排除，否則刪掉的會復活。
- 合併穩定滿 7 天才移除 localStorage 舊備份（期間雙保險）。
- IndexedDB 不可用（極舊環境/隱私模式）→ 整層退回 localStorage，行為與舊版相同。

**API**：`init / getAll / setAll / flush / bytes / mode / dayCount`

## 13. 穩定性機制（血淚史）

> **背景**：WKWebView 網頁行程會被 iOS 因記憶體壓力砍掉（司機同時跑導航 App 時最兇），歷經 v223–v239 多輪修復。**勿隨意刪除這些機制。**

### 13.1 發燙三元兇（已修）
1. 羅盤 60Hz 抖動驅動旋轉動畫 → 節流 + 死區 2.5°/3°
2. 紅燈怠速跟隨動畫 → 3m 移動門檻
3. 精度圈每秒重畫 → 3m/3m 門檻

### 13.2 index.html 開機腳本（順序重要）
1. **`__mtLog` 黑盒子**（`mt_bootlog` 環狀 80 筆）：檢視器＝歷史底部版本號**連點 3 下**；5 下＝診斷模式。
2. **`__mtSafeReload` 防迴圈重載**：180 秒窗 > 4 次 → reloadloop → 停止 + 轉標準。
3. **開機看門狗**：25 秒未 `__mtBooted` → safeReload。
4. **崩潰偵測 v3（心跳式）**：app.js 每 5 秒寫 `mt_alive`；載入時「導覽型態=navigate 且 mt_alive < 45 秒」＝被系統砍掉 → `mt_crash` 30 分鐘窗累積 4 次 → crashloop → 標準 3 小時。
   （v2 靠 sessionStorage 消失判斷 → 被砍後 sessionStorage 常還在，25 次只抓到 3 次，**勿走回頭路**）
5. **冷啟動自動 reload**（App 殼限定，v244 恢復）：reload 狀態下頂列 safe-area 必定正確。

### 13.3 Service Worker（`sw.js`）
- **導覽網路優先**（no-store）＋4 秒逾時/離線退快取（**隧道白屏救星**）。
- 自家 `?v=` 資源與鎖定版本函式庫（leaflet/maplibre）快取優先；Google/向量圖磚不攔截。
- 快取名帶版本、activate 汰舊。

### 13.4 GL 全路徑保險（`gl-compat.js`）
- maplibregl 缺失→默默 return；WebGL 探測失敗→return；Map 建構 throw→記 jsfail + safeReload；webglcontextlost 5 秒未復原→safeReload；3D 建築隱藏省記憶體；pixelRatio ≤ 2、maxTileCacheSize 24。

### 13.5 原生保險（`native/MainViewController.swift`）
- `didBecomeActive` 探測 JS 環境（`typeof INDEX_VERSION`），死了 `webView.reload()`——**背景被砍回來全白的原生解**。已寫好，待使用者下次接 Xcode 重簽時換入生效。

## 15. 部署與更新機制

**每次改功能都要完整走完**：
1. **升版號 4 個地方**：`js/app.js` `APP_VERSION`、`index.html` `INDEX_VERSION`、`version.json`、`sw.js`（版本註解＋`VER` 快取名）。
2. commit 到 `claude/mobile-website-version-Sl6cq` 分支並 push。
3. **同一個 commit 也 push 到 `gh-pages`**：`git push origin HEAD:gh-pages`。
4. **驗證 Pages deploy conclusion=success**（常有暫時性失敗；失敗就空 commit 重觸發）。`actions_list` 回應超過 token 上限 → 用 python 解析存檔 JSON。
5. **使用者更新方式：完全關閉 App 再開兩次**（Service Worker 換版：第一次安裝、第二次生效）。

> **為什麼關兩次**：Service Worker 的生命週期是「install → waiting → activate」。舊 SW 還控制著頁面時，新版只是先下載安裝在旁邊待命；下一次冷啟動才接管生效。

## 16. 測試策略

**環境**：Playwright + 沙箱 Chromium（外部網路全擋，函式庫從 npm 供應、OSRM/Firebase 用 mock）。

**原則**：
- 每個修復都要有對應的 Playwright 測試與回歸。
- 測試 context 一律 `serviceWorkers:'block'`（SW 有專屬測試）。
- **純函式優先測**：`MaptripFinance._analyzePickups`、`MaptripHotspots._buildHistoryNow` 等刻意抽出來供離線單元測試。
- 載 app.js 做 DOM 測試時：stub `TripStore.init` 讓它永不 resolve（不 boot、不需地圖）、stub `L`（top-level `TILE_LAYERS` 需要）；app.js 的 function 宣告會蓋掉 window 同名屬性，故 `loadTrips`/`saveTrips`/`toast` 要**載入後**才覆寫。

**既有測試**（scratchpad，容器重啟會消失需重建）：`failsafe.js`、`swtest.js`、`heatfix.js`、`snaptest.js`、`memfix.js`、`glhide.js`、`pktest.js`（上車熱點）、`hstest.js`（即時熱區）、`faretest.js`（叫車費切換＋批次抽成）。
