# 記帳者模式 — 功能、運作與交接文件

> 給下一個 session 的交接文件。涵蓋「記帳者」整個功能：它是什麼、兩種角色的流程、資料模型、
> **程式在哪個檔案的哪個函式**、雲端同步怎麼運作、安全根（Firestore 規則）、血淚坑、測試檔。
> 對應程式：`js/bookkeeper.js`、`js/sync.js`、`js/sync-ui.js`、`js/desktop-mode.js`、`js/manual-trips.js`、
> `js/finance.js`、`js/app.js`（applyCommission / 顯示層合併）、`docs/記帳者-firestore規則參考.md`。

---

## 0. 一句話

「記帳者」讓司機把**看帳/記帳的工作授權給另一個人**（例如老婆、車行會計）。授權後那個人（記帳者）
能**唯讀司機的行程**、**編輯每趟的抽成/叫車費**、**記支出**、**代補登漏記的趟**，以及（司機另外開開關後）
**修改車資**。雙方即時同步。**安全界線完全由 Firestore 規則保證，不在 App 程式裡。**

---

## 1. 兩種角色（同一個面板、同一支程式）

「記帳者」面板（`js/bookkeeper.js` 的 `renderHome`）同時服務兩種身分：

| 區塊 | 角色 | 做什麼 |
|---|---|---|
| 🧾 我協助記帳的司機 | **當記帳者** | 輸入司機給的邀請碼加入 → 點司機進去看行程、編抽成/支出、補登 |
| 👤 授權我的記帳者 | **當司機** | 產生邀請碼給別人 → 對方輸入後即授權；可撤銷；**可開「允許記帳者改車資」開關** |

> 一個帳號可以同時是「某人的記帳者」又「授權別人當自己的記帳者」。

## 2. 使用者流程

### 2.1 授權（司機端）
1. 司機開「記帳者」面板 → 「＋ 產生邀請碼給記帳者」（`invite()` → `MaptripSync.createInvite`，寫 `invites/{CODE}`）。
2. 把碼給記帳者。記帳者「＋ 輸入邀請碼加入一位司機」（`join()` → `redeemInvite`，回填 `invites/{CODE}.claimedBy`）。
3. **司機下次開一次 App**：`processInviteClaims` 掃自己的邀請碼，把已 `claimedBy` 的記帳者寫進
   `users/{司機}/meta/access.bookkeepers`（**這一步是授權真正落地**；記帳者要等這步才讀得到）。
4. 撤銷：司機「撤銷」（`removeBk` → `removeBookkeeper`）→ 從 bookkeepers 移除、把該碼標 `revoked`。

### 2.2 記帳者看司機、編抽成
- 點司機卡片 → `openDriver` → `loadDriver`（`readDriverData`）→ `paintDriver` 畫月報表 + 每趟列。
- 點某趟 → inline 展開編輯抽成/叫車 → `saveComm` → `writeCommission` 寫 `commissions/{tripId}`。
- 司機端 `commissions` 有 onSnapshot，改動即時套回本機（見 §4）。

### 2.3 代補登（#1，v328）
- 記帳者在某天「＋新增紀錄」→ `addTrip`/`saveTrip` → `writeManualTrip` 寫 `manualTrips/{id}`（**不寫進 days**）。
- 司機 App 訂閱自己的 `manualTrips`，**顯示層合併**進今日/歷史（標「手動」、可刪）。詳見 §5。

### 2.4 改車資（#3，v328）
- **預設關**。司機在「記帳者」面板『授權我的記帳者』區點開關（`toggleFareEdit` → `setAllowFareEdit`，
  寫 `meta/access.allowFareEdit=true`）。
- 開了之後，記帳者編輯某趟時才會出現「車資」輸入框，存檔寫 `commissions/{tripId}.fareOverride`。
- 司機端讀到 `fareOverride` 就套進 `t.fare`（沿用抽成同一條路徑）。安全由規則把關（§6）。

## 3. 資料模型（Firestore）

```
users/{driverUid}/
  days/{day}                    行程（司機寫；記帳者唯讀）        { trips:[...] }
  commissions/{tripId}          抽成/叫車 + 車資覆蓋              { commission, dispatch, fareOverride?, payOverride?, updatedAt, by }
  expenses/{expId}              支出（加油等；記帳者可讀寫刪）      { cat, amount, note, day, ts }
  manualTrips/{id}              記帳者代補登（不進 days）          { fare, paymentMethod, startTime, day, label, manual:true, by }
  meta/access                   授權清單 + 車資開關               { bookkeepers:{uid:name}, allowFareEdit:bool }
  meta/profile                  司機名（記帳者可讀，顯示用）        { name }
users/{bookkeeperUid}/
  linkedDrivers/{driverUid}     記帳者自己的「我協助的司機」清單     { driverUid, name }
invites/{CODE}                  邀請碼                          { driverUid, claimedBy?, revoked?, createdAt }
```

## 4. 雲端同步架構（`js/sync.js`）

### 4.1 司機端訂閱（`pullAndListen`，登入後啟動）
- **`commissions` onSnapshot** → 每筆呼叫 `window.applyCommission(id, commission, dispatch, fareOverride, payOverride)`
  → 套進本機 days + 存檔（記帳者改抽成/車資即時反映）。
- **`manualTrips` onSnapshot** → `MaptripManual.set(list)` + `refreshAfterSync()`（記帳者補登即時顯示）。
- 換帳號 / 登出：`unsubComm`/`unsubManual` 等一起取消；`_clearLocalForSwitch` 清 `MaptripManual`。

### 4.2 `applyCommission`（`js/app.js` 開頭）
- 依 tripId 找到本機那趟 → 套 `commission/dispatch`；若帶 `fareOverride/payOverride`（非 null）→ 套 `t.fare/t.paymentMethod`（並清 `_roadBad`）。
- 有變動才 `saveTrips` + 回 `true`（觸發重畫）；**沿用抽成的「寫 days＋同步」路徑，收支報表自然一致**。

### 4.3 記帳者端一次性讀取（`readDriverData(driverUid)`）
- `Promise.all` 併發讀 6 個：`meta/profile`、`days`（不吞錯＝授權關鍵）、`commissions`、`expenses`、`manualTrips`、`meta/access`。
- 回 `{ days, commissions, expenses, manualTrips, name, allowFareEdit }`。
- 司機本人「收支」頁有「↻ 更新記帳者填的抽成」鈕 → `pullCommissions`（一次性抓自己的 commissions 套進本機）。

## 5. 手動紀錄顯示層合併（`js/manual-trips.js`，`MaptripManual`）

**核心原則：手動紀錄絕不寫進 `days`**（避免污染雲端、避免被司機存檔蓋掉）。只在**顯示/計算時**合併。

- 儲存：記憶體 + 裝置級 localStorage 快取（`maptrip_manual`）；換帳號 `clear()`。
- `set(list)`（雲端快照灌入）、`forDay(day)`（該天手動趟，標 `_manual`、依 startTime 排序）、
  `mergeDay(dayTrips, day)`（GPS+手動交錯排序）、`mergeInto(daysMap)`（給收支算營收）、`days()`、`remove(id)`。
- 消費端：
  - `app.js renderTripSheet`（今日）、`renderHistorySheet`（歷史）用 `mergeDay` 併入；GPS 列用「真實索引」呼叫既有 handler，手動列走 `_manualRowHtml` + `deleteManualRow`（→ `deleteManualTrip`）。
  - `finance.js revenueOfMonth` 用 `mergeInto` 把手動車資算進月營收（工時 `workMs` 內部排除手動＝無 endTime）。

## 6. 安全根：Firestore 規則（**不在 repo，必須由使用者部署**）

**App 程式完全信任規則。**「記帳者只能讀行程、可寫抽成、車資要授權才可改、看不到別人」這條界線**只由規則保證**。

- 規則範本與逐條測試：**`docs/記帳者-firestore規則參考.md`**（含 `isBookkeeper`、`allowsFareEdit`、
  `fareOverrideUnchanged/payOverrideUnchanged` 三個 function，以及 commissions 的授權寫入條件）。
- 關鍵：`commissions` 一般抽成/叫車記帳者可寫；但帶 `fareOverride/payOverride` 且有改動時，
  需 `meta/access.allowFareEdit==true` 才准。`meta/access` 的 write 只限司機本人。
- **交接提醒：我（開發端）無法用第二帳號實測規則**，每次動到 commissions/manualTrips/access 的欄位語意，
  都要提醒使用者用 Rules Playground＋真實第二帳號跑 doc 裡的第 1–11 項。

## 7. 電腦滿版記帳者模式（`js/desktop-mode.js`，`MaptripDesktop`）

- 瀏覽器（非原生 App）可手動切「記帳者模式」（旗標 `maptrip_review`，`isReview()`）。
- `mountHome()` 建純覆蓋層 `#bk-home`（鋪地圖上、不 re-init 地圖），把 `bookkeeper.js` 的首頁掛滿版。
- 藏 GPS/找客/定位；保留記帳者/歷史/回放/雲端同步/收支。**原生 App 永遠司機版**（`apply()` 直接 return）。
- 登入後 `app.js renderSyncPanel` 在 review 模式會自動 `mountHome()`。

## 9. 血淚坑 / 注意事項（勿踩）

1. **授權要司機開一次 App 才落地**：`processInviteClaims` 在司機端跑。記帳者「讀不到司機」最常見原因＝
   ①司機還沒開 App 完成授權 ②規則沒部署。`loadDriver` 已把 `permission-denied` 直接顯示給使用者。
2. **手動紀錄不進 days**：一旦寫進 days 會被司機 App 的存檔蓋掉、且污染雲端同步評分。永遠只做顯示層合併。
3. **車資覆蓋放 commissions、不是改 days 雲端**：司機端 `applyCommission` 把 override 套進本機 days 再同步；
   記帳者本身不寫司機 days（規則也擋）。
4. **onclick 名字注入**：記帳者列的 onclick **只帶 uid、名字查表**（`esc()` 不跳脫單引號，名字含 `'` 會跳出字串）。
5. **一碼一用 / 撤銷持久化**：`_claimBlock`（已被別人兌換擋下）、撤銷時把碼標 `revoked`＋`_shouldAuthorize` 跳過。
6. **換帳號隔離**：`_clearLocalForSwitch` 要一併清 `MaptripManual`、取消 `unsubComm/unsubManual`、`resetExpenseSync`。
7. **工時排除**：`util.js workMs` 排除 `paymentMethod==='other'` 與無 endTime 的手動趟（避免灌水工時）。
8. **規則我無法實測**：任何動到 commissions/manualTrips/access 欄位語意的改動，務必提醒使用者第二帳號實測。
